What is ADP?

The Application Deployment Platform (ADP) is a self-service tool that lets engineering teams provision infrastructure, manage continuous integration and deployment (CI/CD) pipelines, and monitor application health—without needing to request help from DevOps teams.

Who Should Use This Guide?

This guide is designed for:

  • Frontend developers
  • Backend developers
  • Full-stack developers
  • Anyone responsible for deploying applications

Why Use ADP?

⚡ Faster Deployments

Get your applications live in minutes, not hours. No more waiting for manual infrastructure setup.

🎯 Self-Service Control

Manage your own infrastructure and pipelines without submitting tickets or waiting for approvals.

🔄 Consistency

Ensure your staging environment matches production with one-click synchronization.

💰 Cost Visibility

Track and control your infrastructure costs with built-in tagging and cost reporting.

Getting Started

Prerequisites

Before you can access the ADP platform, make sure you have:

  • Active company credentials for single sign-on (SSO)
  • Manager approval via your company's Access Request Portal
  • Your team's cost center code (needed to track infrastructure spending)
💡 Tip: If you don't have a cost center code, contact your finance or operations team to get one before proceeding.

Step-by-Step Onboarding

Follow these 4 steps to deploy your first service using ADP:

  1. Log In

    Visit the ADP portal and log in using your company email address and password.

  2. Create a New Project

    In the left sidebar, click the "Projects" tab, then click "Create New Project".

    📋 Example: Name your project something descriptive like "user-auth-service" or "payment-processor".
  3. Choose a Template

    Select the "Microservice Template (Node.js/Python)" option that matches your application's programming language.

    💡 Tip: The template comes pre-configured with industry best practices and common libraries you'll need.
  4. Provision Your Infrastructure

    Enter your project's repository URL and click "Provision Assets". ADP will automatically:

    • Create a PostgreSQL database
    • Set up a Redis cache
    • Create S3 storage buckets
    • Generate a CI/CD pipeline configuration
✓ Congratulations! Your application is now deployed and your CI/CD pipeline is active. Code commits will automatically trigger builds and tests.

Environment Configurations

ADP provides three standard environments for your applications. Each has different settings optimized for its purpose:

Environment Purpose Log Level Maximum Resources
Development Local testing and experimentation DEBUG (verbose logging) 2 container instances (pods)
Staging Pre-production testing with realistic data INFO (standard logging) 5 container instances (pods)
Production Live environment serving real users WARN (only warnings and errors) 20 container instances (pods)
💡 What are Pods? A pod is a lightweight container that runs your application code. The "maximum resources" column shows how many copies of your application can run simultaneously to handle traffic.

Troubleshooting & Frequently Asked Questions

Why is my build failing at the "Code Quality Check" step?

This usually occurs when your code repository is missing a proper code quality configuration file. Here's how to fix it:

  1. Check that your project has a sonar-project.properties file in the root directory
  2. Ensure your tests are running and generating coverage reports
  3. Verify that test coverage meets your team's minimum threshold
📋 Example: If your project uses Jest for testing, ensure your package.json includes a coverage script: "coverage": "jest --coverage"

How do I request additional resources for load testing?

If you need to temporarily increase your resource limits for testing your application under heavy load:

  1. Contact your platform operations team
  2. Specify the environment (staging or production) and how many additional resources you need
  3. Include the date and duration of your load test
  4. Allow 24 hours for review and approval

How do I rollback a deployment?

If you deployed code that's causing issues:

  1. Go to your project's "Deployments" tab
  2. Find the previous working version in the deployment history
  3. Click "Rollback to This Version"
  4. ADP will immediately revert to the previous code

Can I deploy to production during business hours?

Yes, ADP supports deploying 24/7. However, best practices recommend scheduling major deployments during low-traffic times. Check with your team about deployment windows.

How do I set environment variables for my application?

To add environment-specific configuration:

  1. Go to your project settings
  2. Click "Environment Variables"
  3. Add your key-value pairs for each environment (Development, Staging, Production)
  4. Your application will automatically pick them up on the next deployment
⚠️ Security Note: Never store passwords, API keys, or secrets in environment variables in the platform UI. Use your company's secure secrets management system instead.
